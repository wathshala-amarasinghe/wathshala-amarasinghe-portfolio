# Portfolio audit — 25 November 2026

The live site served the homepage and all five case studies over HTTPS. Its largest confirmed issues were vulnerable dependency versions, KAVON content clipped at the desktop breakpoint, mobile navigation that stayed keyboard-focusable when closed, and duplicated sample testimonials. The working tree contains the fixes. The live site was used as the before baseline and was not redeployed.

| Area | Verified inventory |
| --- | --- |
| Public pages | `/`, `/work/kavon`, `/work/lumi`, `/work/smart-web-pos`, `/work/nation-spice`, `/work/lmt-go`. Next.js pre-renders all six. Unknown routes return 404. |
| Homepage | Intro, About, Work & Experience with a certificate, Work with four filters and five cards, Services, Tech Stack, Contact and a footer credit. A sample Testimonials section was present before this audit. Desktop rail and mobile menu target homepage anchors from any case study. |

One Node.js route handler, `POST /api/contact`, sends to a server-configured recipient using Nodemailer and Gmail SMTP. No portfolio authentication, admin panel, sessions, database, uploads or Server Actions were found. KAVON admin features described in the case study belong to the external demo. |

## Findings and fixes

| Severity | Finding and evidence | Impact and root cause | Fix and verification |
| --- | --- | --- | --- |
| Critical | `package-lock.json` resolved Next.js 16.3.8. `npm audit --json` flagged critical and high Next.js advisories. The Next.js Image Optimizer is active. No app use of Server Actions or `use cache` was found. | The installed version was in affected ranges. Exploitability depends on configuration and routes and was not established. | Upgraded Next.js and its ESLint config to 16.4.6 within the same major. The production build and route suite passed. [Next.js support policy](https://nextjs.org/support-policy) |
| Medium | The registry also flagged Nodemailer address parsing and transitive lint dependencies. The contact route supplies visitor input to `replyTo`, while the SMTP recipient comes from server configuration. The Zod and minimatch advisories appeared in the ESLint dependency tree. | Runtime mail dependency required patching. The identified lint dependencies are used in tooling. | Upgraded Nodemailer to 10.6.1 and refreshed the affected transitive dependencies within compatibility ranges. Full audit went from 10 flagged packages to 0. [Nodemailer releases](https://github.com/nodemailer/nodemailer/releases) |
| Medium | `src/app/api/contact/route.ts` read the entire body before enforcing the byte cap when no length was declared. It accepted media type prefixes and contained no attempt quota before SMTP. | Excess request bytes could be buffered before validation. Valid repeated submissions could consume delivery capacity. | Enforced exact JSON media type, capped streaming reads at 16 KiB and five seconds, tightened mailbox syntax, and added a bounded per-instance SMTP quota with HTTP 429 and Retry-After. Stream-cap and quota tests use local data and make no SMTP calls. [Vercel request headers](https://vercel.com/docs/headers/request-headers) |
| Medium | Load `/work/kavon` at 1024 CSS px. The live document exceeded the viewport by 195 px and controls were clipped. | The grid's intrinsic minimum and a fixed-width inner column forced overflow. | Allowed the shell's main column to shrink and stacked the cart block until the larger breakpoint. The same width measured 0 px overflow locally. |
| Medium | Test the menu, certificate and KAVON image viewer with the keyboard. Closed mobile navigation was only visually hidden. The two original image overlays did not put focus inside or make the background inert. | Keyboard and assistive-technology users could reach hidden controls, or interact behind a modal. | Switched the three overlays to native dialogs with focus entry, Escape and return to trigger. Removed hidden scroll controls from tab order and improved the skip link. Browser keyboard tests cover the main cases. |
| Medium | Run axe on the live homepage, KAVON and LMT GO at mobile and desktop width. Low-contrast accent labels, muted text and buttons were flagged. The shared sidebar also added a second visible H1 on each route. | Dark accent colours used for text, and a profile heading shared across routes, reduced readability and heading clarity. | Kept burgundy surfaces and introduced a lighter text and focus token. Gave buttons, form borders and KAVON CTAs stronger contrast. Converted the sidebar greeting to ordinary text. Re-ran route scans on the production build. |
| Medium | Scroll to Work with motion enabled. The live browser requested the 9,739,426-byte LUMI video. Several previews and the hero role updated automatically, and the background video could start without a play control. | Large downloads and ongoing motion could interrupt reading and increase data use. The role carousel also presented several labels as current employment. | Switched the homepage cards to existing still covers and kept the LUMI player and image galleries on case studies. The hero uses the current role already recorded in site data. Background video is desktop opt-in with a Stop button. The local default Work-scroll run requested zero MP4s. [WCAG Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) |
| Medium | Contact UI treated any successful HTTP response as delivery success and had no live feedback region. A non-JSON failure surfaced a parsing error instead of useful feedback. | A visitor could lose the text they entered or miss the delivery result. | Requires explicit success, prevents overlapping submissions, preserves text on failure, adds announced feedback and a direct email fallback, and times out stalled browser requests. Intercepted failure and success paths verified in Chromium. |
| Medium | The homepage contained two identical quotes attributed to the same generic placeholder. | Sample text was presented as an endorsement. No approved attribution was available. | Removed the sample section and its navigation entry. The real project, education, role and experience records were preserved. Restore this section only with verified and approved copy. |
| Low | A `ProfilePage` identifying the homepage appeared on every case study. All sitemap routes shared one site-wide `lastmod` value. | Page markup described the wrong page type and a single timestamp did not document route-level changes. | Moved the profile graph to the homepage, scoped the canonical to the appropriate page and emitted a maintained homepage date. Projects use their existing self-canonicals and are listed without unverified timestamps. [Google profile-page guidance](https://developers.google.com/search/docs/appearance/structured-data/profile-page) · [Sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap) |
| Low | Unknown work slugs returned a framework 404 without a portfolio return link. Its response included both Next.js's `noindex` and the root layout's `index, follow`. | A visitor arriving through a stale link had no in-page recovery action. The inherited directive contradicted the 404 directive. | Added a themed 404 with a return link and removed the inherited robots tag. Public indexable pages use the standard default. The regression checks the 404 status, `noindex` and return to the homepage. |
| Low | Live Chromium requested Google Fonts CSS but the body and H1 resolved to the same system stack. The referenced font variables were undefined. Local self-hosted WebKit also upgraded same-origin loopback HTTP asset requests under the production CSP, leading to SSL failures. | An unused external request could delay rendering. The same policy broke CSS and JS when the production build was served over HTTP for local testing. | Removed the unused import, retained the observed system stack and removed Google host allowances. Kept upgrade-insecure-requests on Vercel. Added a build verification on loopback and used real HTTPS for the live checks. |

## Verification and measurements

| Check | Before on live Vercel | After on the local production build |
| --- | --- | --- |
| KAVON at 1024 CSS px | 195 px horizontal overflow | 0 px overflow |
| Visible page H1 count | Two across the six tested routes | One per route |
| Default Work section scroll | Requested the LUMI MP4, whose full stored size is 9.74 MB | No MP4 request. Explicit homepage background playback and the LUMI case-study controls remain available. |
| Homepage decoded HTML | 156,313 bytes | 140,006 bytes |
| Homepage decoded script resources | About 673 KB | About 688 KB after the dependency and code updates |
| Homepage lab LCP and CLS | Sampled at 1.68 s and 0.0036 | Sampled at 0.44 s and 0.0033 during local verification |

The lab samples used Chromium's PerformanceObserver. Network conditions and hosts differed, so these timings are descriptive measurements rather than a production speedup claim. Lighthouse, INP, and real-user field data were not collected.

- Chromium rendered all six public routes at 320, 375, 390, 768, 1024, 1280 and 1440 CSS px. Firefox and WebKit rendered all six at 390 and 1280 px. The responsive sweep found no horizontal viewport overflow after the layout fix. All three engines passed keyboard open, Escape and focus restoration for the mobile menu and certificate. Chromium also checked the KAVON lightbox.
- Landscape coverage used 844 × 390. Reflow coverage used 640 and 320 CSS px, corresponding to the available width of a 1280 px layout at 200% and 400% zoom. Native browser zoom and physical phones were outside this run.
- A browser crawl checked 27 same-origin link targets and 59 per-page local media references with no missing targets. The home filter, KAVON disclosure and back navigation, CV download, same-page and cross-route anchors, and reduced-motion playback paths were exercised. The CV was checked by transfer and file type. With JavaScript disabled, the homepage heading and all five project links were still available.
- Axe found zero violations in 12 final scans across all six routes at 390 and 1440 px using WCAG-tagged rules. The final reduced-motion check verifies that the hero heading stays visible through hydration. Early screenshot captures exposed an animation regression in the first patch, and the capture was repeated after the fix. The final previews compare matched widths with the profile identity areas masked. The layout and font stack remain consistent, with intentional contrast, motion and content changes.
- `npm run build`, `npm run lint`, `npm run typecheck` and `git diff --check` passed. With `PORTFOLIO_TEST_PRODUCTION=1` and `PORTFOLIO_TEST_PORT=3101`, `npm test -- --reporter=dot --workers=4` returned 48 passed and two viewport-specific skips. `npm audit --json` and `npm audit --omit=dev` reported zero known vulnerabilities. No production browser source maps or configured mail credential identifiers were found in the local public build output.

## Security boundaries and production follow-up

- The live headers included CSP, HSTS (one year on the hostname), frame denial, MIME sniffing protection, a referrer policy and a permissions policy. The CSP retains inline script and style allowances for Next.js hydration and existing style usage. The application supplies no upload or user-authored page HTML surface. JSON-LD is static site data with less-than characters escaped. A strict nonce or hash CSP needs a separate static-rendering compatibility check.
- No real email or transaction was sent, and no exploit reproduction or load testing was performed. The working tree and tracked environment file list showed only an environment example committed. No provider secrets are printed here. Production environment configuration, private logs, and provider-level firewall rules were not available for inspection.
- The SMTP quota is local to a running instance. After deployment, use the Vercel dashboard to check whether a shared rate limit is available for `POST /api/contact`, confirm stable platform client identification and verify SMTP environment settings. If SMTP delivery needs a confirmed end-to-end check, use a staging capture mailbox or an approved production test.
- GitHub profile, KAVON repository and KAVON demo returned HTTP 200. Automated requests for LinkedIn, Behance and both Figma links were declined, so public sharing permissions and visibility remain unverified. Check those links in a signed-out browser before changing them. The existing project destinations were retained.
- Search Console reporting and preview-card caches were outside this audit. Check indexing and Google-selected canonicals after deployment. The report does not infer ranking from indexability.
- Ask the portfolio owner to verify current availability, credential details and permission to publish CV and certificate material. Case-study results and employment facts were not inferred. Automated accessibility scans and browser role checks cover a subset of WCAG 2.2 AA. Screen-reader testing with a real assistive-technology session remains open.
